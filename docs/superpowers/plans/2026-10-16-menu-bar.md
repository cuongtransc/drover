# Drover Menu Bar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every Drover shortcut is an item of the macOS menu bar carrying its key, and the file actions of Chat's path menu are in File.

**Architecture:** Rust builds File / View / Go / Help from a static layout and keeps the item handles; the frontend sends the bindings and the File target, and runs actions on `menu://action` / `menu://file` events. A key equivalent takes the key before the page (ADR 0010), so the menu is the path a bound key takes in the app; the webview `keydown` listener stays as the fallback outside Tauri (tests, browser harness) and never fires for a menu key in the app.

**Tech Stack:** Tauri 2.12 menus (`tauri::menu`, muda 0.20 accelerators), React + zustand, vitest, cargo test.

**Spec:** `docs/superpowers/specs/2026-10-16-menu-bar-design.md` (decision: `docs/adr/0010-menu-bar-owns-app-shortcuts.md`)

## Global Constraints

- Menu item ids: `action:<ActionId>` (e.g. `action:jump`), `file:reveal`, `file:open`, `file:copy`, `help:guide`, `help:shortcuts`.
- Events to the webview: `menu://action` with payload the `ActionId` string; `menu://file` with payload `"reveal" | "open" | "copy"`; `menu://settings` with payload `null` (Settings… ⌘,) or `"shortcuts"` (Help › Keyboard Shortcuts…).
- Accelerator string: `CmdOrCtrl` then `+Ctrl` / `+Alt` / `+Shift` in that order when set, then `+` and the Chord's `code` unchanged (`CmdOrCtrl+Shift+BracketLeft`, `CmdOrCtrl+KeyK`); muda parses codes directly. A binding of `null` means no accelerator.
- Commands: `menu_set_shortcuts(bindings: HashMap<String, Option<Chord>>)` (Chord = `{ code: String, shift: bool, alt: bool, ctrl: bool }`, serde camel/snake as the frontend's `Chord`), `menu_set_file_target(target: "local" | "remote" | "none")`. Both return `Result<(), AppError>`.
- File target kinds: `"local"` enables Reveal in Finder, Open on this Mac, Copy Path; `"remote"` enables only Copy Path; `"none"` disables all three.
- Labels: View/Go items use `ACTIONS[].label` text from `src/shortcuts/actions.ts` mapped by id in Rust's layout table (copy the exact strings: "Jump to pane" → menu label "Jump to Pane…", etc. as in Task 1's table).
- Guide URL: `https://github.com/cuongtransc/drover/blob/main/docs/guide/00-index.md`.
- The webview `keydown` listener in `App.tsx` is kept unchanged (fallback); the spec's "skips an action the menu carries" is met because the menu takes those keys before the page.
- Every user-facing failure goes through `showToast("Cannot <verb> <path>: <message>")`, as `PathCode` does.

## Review Focus

- Settings recording a key: every Drover accelerator is cleared, so ⌘K reaches the recorder; restored on save, cancel and leaving Settings (Task 3 tests).
- A remote file in Files: Reveal in Finder / Open on this Mac disabled, Copy Path enabled (Task 4 tests).
- Focus on a Chat path wins over the active Open item for File items (Task 4 tests).
- A dialog open (`.overlay`): menu-run actions in `KEPT_BY_DIALOGS` do nothing, as the keys do today (Task 2 tests).
- Rebinding to a chord with Ctrl/Alt/Shift produces a valid accelerator (Task 1 test covers every modifier).

### Task 1: Rust menu bar: layout, accelerators, events, commands

**Files:**
- Create: `src-tauri/src/menu_bar.rs`
- Modify: `src-tauri/src/lib.rs` (`mod menu_bar;`, `app_menu` adds the menus, `on_menu_event` routes, register commands, `app.manage(MenuBar)`)

**Interfaces:**
- Produces: `pub fn accelerator(c: &Chord) -> String`; `pub enum Route { Emit(&'static str, Option<String>), OpenGuide }`; `pub fn route(id: &str) -> Option<Route>`; `pub const LAYOUT: &[(&str /*menu*/, &[Entry])]` where `Entry` is `Item { id, label }` or `Sep`; commands `menu_set_shortcuts`, `menu_set_file_target`.

Layout (exact labels):

| Menu | Entries |
|---|---|
| File | `action:tabs.new` "New Tab" · `action:files.goto` "Go to File…" · Sep · `file:reveal` "Reveal in Finder" · `file:open` "Open on this Mac" · `file:copy` "Copy Path" · Sep · `action:item.remove` "Remove Item" |
| View | `action:layout.sidebar` "Toggle Sidebar" · `action:layout.focus` "Focus Layout" · `action:files.toggle` "Toggle Files Panel" · `action:board` "Agent Board" · Sep · `action:font.bigger` "Bigger Font" · `action:font.smaller` "Smaller Font" · `action:font.reset` "Default Font Size" |
| Go | `action:jump` "Jump to Pane…" · `action:triage.next` "Next Blocked or Review" · `action:triage.prev` "Previous Blocked or Review" · Sep · `action:item.next` "Next Open Item" · `action:item.prev` "Previous Open Item" |
| Help | `help:guide` "Drover Guide" · `help:shortcuts` "Keyboard Shortcuts…" |

File items `file:reveal` and `file:copy` carry fixed accelerators `CmdOrCtrl+Alt+KeyR` and `CmdOrCtrl+Alt+KeyC`; `file:open` none. Tauri's default File (Close Window, already removed) is replaced by this File; its default View (Enter Full Screen) is kept below a separator in View; Help replaces the default Help. Items start disabled for `file:*` and with no accelerator for `action:*` until the frontend sends bindings.

mod tests {
    use super::*;
    fn c(code: &str, shift: bool, alt: bool, ctrl: bool) -> Chord {
        Chord { code: code.into(), shift, alt, ctrl }
    }
    #[test]
    fn accelerators_for_every_modifier_and_default_key() {
        assert_eq!(accelerator(&c("KeyK", false, false, false)), "CmdOrCtrl+KeyK");
        assert_eq!(accelerator(&c("KeyJ", true, false, false)), "CmdOrCtrl+Shift+KeyJ");
        assert_eq!(accelerator(&c("BracketLeft", true, false, false)), "CmdOrCtrl+Shift+BracketLeft");
        assert_eq!(accelerator(&c("Equal", false, false, false)), "CmdOrCtrl+Equal");
        assert_eq!(accelerator(&c("Digit0", false, false, false)), "CmdOrCtrl+Digit0");
        assert_eq!(accelerator(&c("KeyR", true, true, true)), "CmdOrCtrl+Ctrl+Alt+Shift+KeyR");
        for code in ["KeyK", "BracketRight", "Minus", "Comma", "Backquote", "Space", "Tab"] {
            let a = accelerator(&c(code, true, true, true));
            assert!(a.parse::<tauri::menu::Accelerator>().is_ok(), "{a}");
        }
    }
    #[test]
    fn every_action_is_in_the_layout_once() {
        let ids: Vec<&str> = LAYOUT.iter().flat_map(|(_, e)| e.iter()).filter_map(Entry::id).collect();
        for a in ["jump", "triage.next", "triage.prev", "board", "layout.sidebar", "layout.focus", "tabs.new",
                  "files.toggle", "files.goto", "item.remove", "item.prev", "item.next", "font.bigger", "font.smaller", "font.reset"] {
            assert_eq!(ids.iter().filter(|i| **i == format!("action:{a}")).count(), 1, "{a}");
        }
    }
    #[test]
    fn routes() {
        assert_eq!(route("action:jump"), Some(Route::Emit("menu://action", Some("jump".into()))));
        assert_eq!(route("file:reveal"), Some(Route::Emit("menu://file", Some("reveal".into()))));
        assert_eq!(route("help:shortcuts"), Some(Route::Emit("menu://settings", Some("shortcuts".into()))));
        assert_eq!(route("help:guide"), Some(Route::OpenGuide));
        assert_eq!(route("settings"), Some(Route::Emit("menu://settings", None)));
        assert_eq!(route("quit"), Some(Route::Emit("app://quit-requested", None)));
        assert_eq!(route("action:"), None);
        assert_eq!(route("other"), None);
    }
}
